# ПР9. ТКО-Логистика — подтверждение вывоза контейнера

Практическая работа №9 по дисциплине «Сетевые технологии».
Один сценарий: **К5.2 «Подтверждение вывоза контейнера»**, роль — водитель.

Цепочка, которую показывает работа:

```
кнопка «ВЫВЕЗЕНО» в driver.html
        ↓ POST /api/pickups
FastAPI (prilozhenie)
        ↓ Beanie
MongoDB, коллекция pickups
        ↓ GET /api/pickups/{pickup_id}
Swagger UI и карточка результата в интерфейсе
```

Поля в интерфейсе, в MongoDB и в ответе Swagger совпадают.

## Запуск

1. Дважды щёлкнуть `zapusk.cmd` (он поднимет MongoDB на 27017 и приложение).
2. Открыть интерфейс: <http://127.0.0.1:8090/>
3. Swagger: <http://127.0.0.1:8090/docs>

Если MongoDB уже запущена, `zapusk.cmd` её не дублирует. Порт 8090 выбран потому,
что 8080 занят служебным процессом; при необходимости порт меняется в `zapusk.cmd`
и в `.env`.

На этой машине на диске C: мало свободного места, поэтому данные MongoDB
хранятся в `D:\pr9_tko_mongo`; путь задаётся переменной `MONGO_DBPATH` в `zapusk.cmd`.
Тестовая база создаётся в `.data\mongo_test` и удаляется после прогона,
чтобы 100-МБ журналы WiredTiger не накапливались.

## Сценарий показа

1. Открыть интерфейс — точка 1 из 10, контейнер `c14`, адрес «ул. Менделеева, 15»,
   заполненность 82 %.
2. Нажать **«ВЫВЕЗЕНО»**.
3. Справа появляется карточка «Запись создана»: `pickup_id`, задание, точка, адрес,
   заполненность 82 % → 0 %, время (UTC, ISO), статус и ключ идемпотентности.
   Карточка фиксированная, её можно закрыть крестиком и посмотреть карту.
4. Открыть ссылку **«Открыть GET в API»** или Swagger → `GET /api/pickups/{pickup_id}` —
   те же поля.
5. Проверить MongoDB:

```
.venv\Scripts\python.exe skripty\posmotret_bd.py
.venv\Scripts\python.exe skripty\proverit_bd.py
.venv\Scripts\python.exe skripty\proverit_bd.py P-XXXXXXXX
```

`posmotret_bd.py` показывает всю коллекцию `pickups` таблицей и полный JSON
последнего документа — это прямой запрос к MongoDB через Beanie.
Для визуального показа базы можно использовать MongoDB Compass
(подключение `mongodb://127.0.0.1:27017`, база `tko`, коллекция `pickups`)
или расширение MongoDB for VS Code.

Скриншоты для отчёта лежат в `docs/`:

- `docs/ui_result.png` — интерфейс после нажатия «ВЫВЕЗЕНО» с карточкой записи;
- `docs/swagger.png` — список методов в Swagger;
- `docs/swagger_get.png` — ответ `GET /api/pickups/{pickup_id}` в Swagger;
- `docs/ui_error.png` — ошибка 422 в интерфейсе: красный статус и сообщение.

## API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/pickups` | создать акт вывоза (основной сценарий) |
| GET | `/api/pickups` | список актов, фильтр `?task_id=T-245` |
| GET | `/api/pickups/{pickup_id}` | получить акт по ID |
| DELETE | `/api/pickups/{pickup_id}` | удалить акт (демонстрация в Swagger) |

Повторный POST с тем же `idempotency_key` не создаёт дубль: возвращается код 200
и уже созданная запись. Новый акт — код 201.

### Удаление в Swagger

Да, в Swagger можно удалять записи: `DELETE /api/pickups/{pickup_id}` → «Try it out».
После удаления `GET` по этому ID возвращает 404. В интерфейсе кнопки удаления нет —
удаление вынесено в Swagger, чтобы не смешивать его с основным сценарием создания.
Список записей тоже доступен в Swagger через `GET /api/pickups`.

## Тесты

```
skripty\zapustit_testy.cmd
```

или:

```
.venv\Scripts\python.exe -m pytest
```

Что проверяется:

- `testy/test_api.py` — POST/GET/список, идемпотентность, 422 на неверные данные,
  неверный JSON, пропущенное `idempotency_key`, 404 на неизвестный ID, удаление;
- `testy/test_bd.py` — документ в MongoDB совпадает с ответом API, удаление
  действительно удаляет документ;
- `testy/test_interfeys.py` — два теста Playwright: успешный сценарий
  (кнопка → GET → MongoDB) и ошибка 422 (интерфейс показывает красный статус
  и сообщение «Некорректные данные»).

Тесты сами поднимают отдельный `mongod` на свободном порту и используют
отдельную базу, поэтому не трогают рабочую базу `tko`. Всего 16 тестов:
12 проверок API (включая негативные), 2 проверки MongoDB и 2 сквозных
Playwright-теста (успешный и с ошибкой).
